# מפרט הלוח — `outputs/<תאריך>-<נושא>-קופי/`

**קובץ אחד עצמאי.** עברית, RTL, נפתח בדאבל-קליק בכל דפדפן, עובד בלי אינטרנט.
בלי CDN, בלי פונט חיצוני, בלי ספרייה. הכול inline.

## איך בונים — התבנית

**לא כותבים את הקובץ מאפס.** `references/board-template.html` הוא לוח שלם: כרטיסי
וריאציות, כפתורי העתקה (לכל בלוק ולכל וריאציה), `[חסר]` בצהוב, `contenteditable`
עם אוטוסייב ל-localStorage, כרטיס התמונה, סקשן הגוף המלא לדף נחיתה, פאנל והדפסה.

שני צעדים:

1. מחליפים את `/*DATA*/{}/*/DATA*/` ב-`/*DATA*/<JSON>/*/DATA*/` — אובייקט ה-`DATA` שלמטה.
2. **מיתוג:** בראש ה-CSS יש טוקנים `/*THEME:bg*/…/*/THEME*/` (bg, card, ink, muted,
   primary, accent, font, fontHead, radius, border, shadow). מצאת מערכת עיצוב → מחליפים
   את הערך שבין הסימונים. לא מצאת → משאירים כמו שזה (ברירת מחדל נייטרלית).
   `DATA.design.source` מקבל את שם הקובץ שממנו נשאב, והלוח מציג אותו בפאנל.

```bash
python3 - <<'PY'
import json, re, base64
tpl = open('.claude/skills/marketing-copy/references/board-template.html').read()
data = json.load(open('outputs/2026-09-30-נושא-קופי/data.json'))
theme = {"bg":"#FAFAF5","ink":"#0A0A0A","primary":"#6D28D9","accent":"#BEF264",
         "font":"Heebo, Arial, sans-serif","fontHead":"Rubik, Arial, sans-serif",
         "radius":"0","border":"4px solid #0A0A0A","shadow":"8px 8px 0 #0A0A0A"}   # מה שנמצא, ולא יותר
for k, v in theme.items():
    tpl = re.sub(r'/\*THEME:%s\*/.*?/\*/THEME\*/' % k, '/*THEME:%s*/%s/*/THEME*/' % (k, v), tpl)
open('outputs/2026-09-30-נושא-קופי/קופי.html','w').write(
    tpl.replace('/*DATA*/{}/*/DATA*/', '/*DATA*/' + json.dumps(data, ensure_ascii=False) + '/*/DATA*/'))
PY
```

התמונה נכנסת ל-`DATA.image.dataUri` כ-base64. **תמונת 2K שוקלת ~5MB** — לפני
ההטמעה מקטינים לרוחב 1024 (`sips -Z 1024` במק) כדי שהלוח יישאר קובץ שנפתח מהר.
הקובץ המלא נשמר ליד הלוח כ-PNG.

## לוח אחד לכל פורמט

| מה ביקשו | שמות הקבצים |
|---|---|
| פורמט אחד | `קופי.html` |
| כמה פורמטים | `קופי-פוסט.html` · `קופי-מייל.html` · `קופי-מודעה.html` · `קופי-דף-נחיתה.html` |

**לוח לכל פורמט, לא לוח אחד עם טאבים.** לכל פורמט `DATA` משלו, מפתח אוטוסייב
משלו, ובחירת וריאציה משלו — ולוח אחד משותף היה מערבב את שלושתם. זה גם אומר
שכל לוח נשלח ונפתח בנפרד, וזה מה שקורה בפועל.

> ⚠️ פורמט אחד לריצה הוא המצב הנפוץ. אל תדרוס `קופי.html` קיים כשמוסיפים פורמט
> שני — עוברים לשמות המפורשים, ומעבירים גם את הקובץ הראשון לשם החדש.

התמונה מוטמעת כ-**data URI** בתוך ה-HTML, כדי שהעברת הקובץ לא תשבור אותה.

## מיתוג הלוח — פרמטרי

**הלוח נראה כמו הסביבה שהוא רץ בה.** אם בתיקיית העבודה יש מערכת עיצוב, הלוח
נבנה בשפה שלה. אם אין — ברירת מחדל נייטרלית ונקייה.

זה נכון גם מעשית: לוח שנראה כמו האתר של המשתמש נקרא כמו שלו, ולא כמו פלט של
כלי חיצוני.

### איפה מחפשים, ועוצרים ברגע שמצאו

| סדר | מקור | מה לוקחים |
|---|---|---|
| 1 | `brand.config.json` · `design-tokens.json` · `tokens.css` · `theme.json` | טוקנים מוצהרים - הכי אמין |
| 2 | `STYLE-GUIDE.md` · `BRAND.md` · `design-system.md` | פלטה, טיפוגרפיה וכללים בכתב |
| 3 | `globals.css` · `app/globals.css` · `styles/` · `tailwind.config.*` | משתני `:root` ו-`--color-*` בפועל |
| 4 | עמוד הבית של האתר בסביבה (`app/page.tsx`, `index.html`) | הפונט, ומה שבאמת מופיע על המסך |
| 5 | אין כלום | **ברירת מחדל נייטרלית** |

**לוקחים ארבעה דברים ולא יותר:** פלטה (2-4 צבעים), משפחת פונט, רדיוס ומסגרות,
וסוג הצל. לא מעבר.

### מה שלא משתנה לעולם

| כלל | למה |
|---|---|
| **צהוב = `[חסר: ...]`** | סמנטי. גם אם בפלטה אין צהוב, החסר צהוב |
| **אדום = `⚠️ טעון בדיקה רגולטורית` בלבד** | אדום על משהו אחר שורף את ההתרעה היחידה שחשובה |
| **הכול inline** | בלי CDN, בלי פונט חיצוני, בלי ספרייה - גם כשמערכת העיצוב טוענת פונט מ-Google Fonts. לוקחים את **שם** המשפחה ונותנים לה fallback מקומי |
| **קריאות לפני נאמנות** | מערכת עיצוב עם ניגודיות נמוכה או פונט דקורטיבי → הלוח **לא** מאמץ אותה. הלוח הוא כלי עבודה שקוראים בו טקסט ארוך |

### אומרים מה עשו

שורה אחת בפאנל ההגדרות ובדוח הסיום: *״הלוח מעוצב לפי `app/globals.css`״*
או *״לא נמצאה מערכת עיצוב - ברירת מחדל נייטרלית״*.

> ⛔ **לא מקבעים פלטה של אף אחד בקוד הסקיל.** הסקיל מותקן אצל אנשים שונים, עם
> מותגים שונים. הצבעים נשאבים בזמן ריצה או שהם נייטרליים - אין אפשרות שלישית.

```js
  brief: { promoting: "...", audience: "...", action: "...", deadline: "..." },
  variations: [{
    id: "a",
    angle: "שאלה",
    closestToVoice: true,       // הווריאציה שהכי מתאימה לפרופיל, עם הסבר
    voiceNote: "4 מתוך 5 מהטקסטים שלך פותחים בשאלה",
    blocks: [                   // המבנה משתנה לפי format
      { label: "הוק", text: "..." },
      { label: "גוף", text: "..." },
      { label: "CTA", text: "..." },
      { label: "האשטגים", text: "..." }
    ],

    missing: ["כמה לקוחות עברו את התהליך"],
    flags: []                   // ["regulatory"] בתחום רגיש
  }],
  image: { file: "post-a.png", dataUri: "data:image/png;base64,...",
           prompt: "...", cost: 0.10, forVariation: "a" },

  // --- דף נחיתה בלבד ---
  // בפורמט landing הווריאציות הן הירו + ציר (3 בלוקים כל אחת), והגוף המלא
  // נכתב פעם אחת, לציר שסומן closestToVoice. ראה formats.md §4.
  fullBodyFor: "a",

              { label: "4. הכאב", text: "..." },
              { label: "CTA ביניים (אחרי הכאב)", text: "..." } ]

```

> ⚠️ **`DATA` הוא הפלט.** מקור האמת הם `brief.md` ו-`voice.md`.
> בנייה מחדש דורסת את ה-HTML — לא עורכים אותו ביד.
> היוצא מן הכלל: עריכות טקסט שהמשתמש עשה בלוח, שנשמרות ל-localStorage.

## המסכים

### 1. ראש הלוח

- הנושא, הפורמט, התאריך.
- **שורת הקול:** `נכתב בקול שלך — voice.md, כויל מ-4 דוגמאות`.
  `calibrated: false` → **באנר צהוב**: *"נכתב בקול גנרי — לא כויל קול.
  תן 3 טקסטים שכתבת ואבנה מחדש."* לא מוסתר, לא בהערת שוליים.
- הבריף כפי שאושר, מקופל.

### 2. הווריאציות — כרטיס לכל אחת

שלושה כרטיסים זה לצד זה בדסקטופ, אחד מתחת לשני בטלפון. בכל כרטיס:

- **תג הזווית** — `שאלה` / `מספר` / `התנגדות`
- **תג `הכי קרוב לקול שלך`** על אחת מהן, עם הסבר מ-`voiceNote`.
  זו הכוונה עדינה — **לא בחירה במקום המשתמש**
- הטקסט, מחולק לבלוקים עם תווית לכל בלוק
- **`[חסר: ...]`** מודגש ברקע צהוב **בתוך הטקסט**, במקום שבו הוא יושב.
  לא נבלע, לא בסוף
- `flags: ["regulatory"]` → פס **`⚠️ טעון בדיקה רגולטורית`** בראש הכרטיס
- **כפתור העתקה** — מעתיק את `full` ל-lipboard, ומציג `הועתק ✓` לשנייה וחצי.
  `navigator.clipboard` עטוף ב-`try/catch`, ובכשל — `textarea` + `select()` כגיבוי
- **כפתור העתקה לכל בלוק בנפרד** — למי שרוצה רק את שורת הנושא או רק את ה-CTA
- **צ'קבוקס "זו שבחרתי"** — בחירה אחת בלבד. הבחירה נשמרת ל-`copy-settings.md`
  ומזינה את הכיול (`voice.md` §למידה מבחירות)

### 3. הגוף המלא — דף נחיתה בלבד

סקשן אחד מתחת לשלושת כרטיסי ההירו, כש-`fullBody` קיים:

- כותרת שאומרת **לאיזה ציר** הגוף נכתב, ושורה אחת: *״שלוש וריאציות של דף שלם
  הן בזבוז, ולכן הגוף נכתב לציר אחד. בחרת ציר אחר? אכתוב את הגוף מחדש אליו.״*
- **כפתור ״העתק את הדף כולו״** בראש הסקשן.
- כל סקשן כבלוק נפרד, עם התווית המלאה (`4. הכאב`, `CTA ביניים`) ו**כפתור
  ״העתק סקשן״** משלו — מי שבונה את הדף מעביר סקשן-סקשן.
- אותן התנהגויות כמו בכרטיסים: `contenteditable`, אוטוסייב, ו-`[חסר]` בצהוב
  בתוך הטקסט.

**שאר הפורמטים לא מקבלים את הסקשן הזה** — בהם הווריאציה **היא** התוצר המלא.

### 4. עריכה בתוך הלוח

הטקסטים הם `contenteditable`. **חובה בלוק האוטוסייב ל-localStorage לפני
`</body>`** — עריכה שנעלמת ברענון הופכת את הלוח למסוכן ולא לשימושי.

מפתח: `marketing-copy:<topic>:<format>`. כל קריאה וכתיבה ב-`try/catch`.
בפאנל: **"אפס עריכות"** שמחזיר לטקסט המקורי.

### 5. הקריאייטיב

מתחת לווריאציה שהתמונה נוצרה עבורה:

- התמונה עצמה, `max-width: 100%`
- **הפרומפט** שממנו היא נוצרה, בטקסט קטן, עם כפתור העתקה —
  כדי שהמשתמש יוכל לייצר וריאציות בעצמו
- **העלות** — `התמונה עלתה $0.10`. שקיפות עלות היא מה שמשאיר אותו משתמש בכלי
- לא נוצרה תמונה → כרטיס עם **הפרומפט בלבד** והסבר בשורה:
  *"אין חיבור OpenRouter — הפרומפט מוכן להדבקה."* **לא כרטיס ריק, לא "בטעינה"**

### 6. פאנל הגדרות מתקפל

**מקופל כברירת מחדל.** בתוכו: הצגת/הסתרת תוויות הבלוקים · אפס עריכות ·
הדפסה · שורה שאומרת מאיזה `voice.md` נכתב ומתי כויל.

## התנהגות

- **חסר מוצג "חסר", לא ריק.** אין תמונה, אין נתון, לא כויל קול — נאמר במלל.
- **עובד בטלפון** — טור אחד. שום דבר לא נגלל לרוחב.
- **הדפסה** — `@media print`: כפתורים, צ'קבוקסים והפאנל נעלמים; הטקסט
  והתמונה נשארים.
- **אדום שמור להתרעות** — `⚠️ טעון בדיקה רגולטורית` בלבד. חסר = צהוב.
  שני אלה לא זזים גם כשהלוח מאמץ מערכת עיצוב (ראה §מיתוג הלוח).

## אחרי הבנייה

פתח את הלוח, ואמור למשתמש **מה נשאר לו לעשות**: לבחור וריאציה, להשלים את
ה-`[חסר]`, ואם בחר — לייצר תמונה.

**אל תשאל "אהבת?".** שאל **"איזו וריאציה?"** — זו שאלה שיש לה תשובה,
והתשובה מזינה את הכיול לפעם הבאה.
